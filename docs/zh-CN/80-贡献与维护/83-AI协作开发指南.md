# AI 协作开发指南

本文面向使用 AI 辅助维护 Zeplod 的开发者，说明如何分工、下达任务、验证结果和控制风险。
模型直接执行的强制规则以仓库根目录 [`AGENTS.md`](../../../AGENTS.md) 为准；本文解释规则背后的协作方法。

## 1. 基本原则

- AI 是实现和审查工具，不是项目事实源或最终审批者。
- 事实冲突时，优先级为：当前代码、Kconfig、CMake、CI 配置 → canonical 文档 → README、示例和历史规划。
- “生成完成”不等于“验证通过”。结论必须附实际命令、退出码和关键输出。
- 硬件、ISR、并发、内存和安全相关结论必须由代码契约、测试或真机证据支持。

## 2. 角色与责任

| 角色 | 责任 | 不应做的事 |
|---|---|---|
| 人类负责人 | 确定目标、授权外部动作、接受风险、最终合并 | 把未核验的模型输出直接视为事实 |
| 主控 | 拆分任务、限定范围、审查实现、汇总证据 | 用子代理日志代替审查 |
| 实现代理 | 在授权范围内修改并完成验证闭环 | 擅自扩大范围、commit、push 或改 CI 策略 |
| 审查代理 | 只读核对目标、风险、风格和证据 | 在“只审查”任务中直接修代码 |

模型名称只属于调用端配置。项目规范应描述“主控、实现、审查”等能力角色，避免因模型升级反复改文档。
如团队必须固定某个模型，只在调用配置或 `AGENTS.md` 的单一位置记录，不把版本号散布到技术手册。

## 3. 标准任务包

一个可执行的任务至少包含：

```text
目标：一句话可验收结果
范围：允许修改的路径；明确禁止区域
约束：风格、Doxygen、安全、Git 与兼容性要求
上下文：关键文件、接口、错误原文和已知决定
验收：必须运行的命令或人工检查项
返回：摘要、改动文件、验证证据、未决项
```

范围必须具体到目录或文件。若实施过程中需要新的权限、硬件、密钥或产品决策，代理应停止相关分支并请求人工决定。

## 4. 验证与证据

最低验证矩阵见根 `AGENTS.md`。回传证据应包含：

1. 完整命令及实际退出码。
2. 成功或失败的关键输出，而不是整段终端日志。
3. 未运行项及原因，例如缺少硬件、SDK 或外部服务。
4. `git diff --check` 和 `git status --short`，用于确认格式与范围。

不能使用“应该通过”“改动很小”替代验证。失败后修复过的命令必须重新执行。

## 5. Zephyr 高风险区域

- **ISR**：仅调用明确标注为 ISR-safe 的 API；禁止阻塞、mutex 和不确定的动态分配。
- **并发与生命周期**：先核对状态机、锁序和 `tests/LIFECYCLE_CONTRACTS.md`，特别关注 stop/shutdown、取消和超时竞态。
- **事件负载**：优先使用 `event_create*` / `event_publish_copy*`，避免手工构造不一致的所有权标志。
- **内存与板型**：区分静态 RAM、线程栈、内核堆和设备树内存；不得把一个板的结论外推到所有目标板。
- **配置**：默认值从 Kconfig 读取；CI 版本和板型从工作流读取；不要复制旧文档中的常量。
- **硬件行为**：没有真机证据时明确写“未验证”，不得声称烧录、时序或外设工作正常。

## 6. 安全、隐私与许可

- 不向模型、日志、Issue 或 PR 粘贴 Token、证书、私钥、客户数据或未脱敏的设备标识。
- 不提交 `zephyr_config.env`、本机绝对路径或内部镜像凭据。
- 使用外部托管模型处理专有源码前，先遵守组织的数据分级和供应商协议。
- 生成代码仍需检查来源、许可证兼容性和第三方声明；不得要求模型复现受版权保护的大段代码。
- 安全机制、加密和密钥管理改动必须人工审查，并执行对应威胁模型与测试。

## 7. 失败与升级

遇到以下情况应交还人类决定：

- 需求存在会改变公共 API、持久化格式、安全边界或产品行为的歧义。
- 验收依赖不可用硬件、私有服务、密钥或外部权限。
- 工作区已有改动与目标重叠，无法确认所有权。
- 同一失败在合理修复后持续复现，或证据与文档互相矛盾且没有更高优先级事实源。

报告阻塞时应给出已经验证的事实、影响范围和可选方案，不得隐藏失败或降低门槛来制造“通过”。

## 8. 推荐回传格式

- **摘要**：完成内容与结论（通过 / 有条件通过 / 不通过）
- **改动文件**：按功能分组，不粘贴长 diff
- **验证**：实际命令、退出码、关键证据
- **未决项**：只列仍需用户决策的事项

## 9. 维护要求

升级 Zephyr、改变 CI 板型、调整测试矩阵或修改公共 API 时，应同时核对：

- 根 `AGENTS.md`
- 本指南
- `docs/zh-CN/00-入门/05-任务导航.md`
- `docs/zh-CN/00-入门/06-代码与文档映射.md`
- 对应 canonical 技术文档

文档检查命令见 `AGENTS.md` 与[参与贡献与代码规范](81-参与贡献与代码规范.md)。
