# 项目配置项说明

本文档整理本仓库 **应用侧 Kconfig**（根目录 `Kconfig` 与 `src/modules/ipc_service/Kconfig`）中各配置项的含义。构建后由 Zephyr 生成 `autoconf.h`，源码中通过 `CONFIG_<符号名>` 使用（如 `CONFIG_EVENT_SYSTEM`）。

- **设置方式**：`prj.conf` 中写 `CONFIG_xxx=y` 或 `CONFIG_xxx=数值`，或使用 `west build -t menuconfig` / `guiconfig`。
- **符号前缀**：下文「配置宏」列即 C 代码中的宏名（与 `CONFIG_` 一致）。
- **与板级/内核选项**：SOC、驱动、内核 heap 等见 Zephyr 与板级 `defconfig`；本表仅覆盖**本应用扩展**的菜单项。

## 1. 事件系统（Event System Configuration）

| 配置宏 | 类型 | 默认值 | 范围 | 含义 |
|--------|------|--------|------|------|
| `CONFIG_EVENT_SYSTEM` | bool | y | - | 是否启用事件系统：发布/订阅、事件队列与分发线程。关闭后依赖事件系统的功能不可用。 |
| `CONFIG_EVENT_MAX_TYPES` | int | 128 | 4-256 | 最大支持的事件类型数量。Kconfig 以 8 个订阅者估算每种类型约 228 字节。完整产品功能需要覆盖到 ID 72；单测使用更高 ID 时显式配置 256。 |
| `CONFIG_EVENT_QUEUE_SIZE` | int | 64 | 4-512 | 全局事件队列可容纳的最大事件个数。过大占 RAM，过小易丢事件。 |
| `CONFIG_EVENT_MAX_SUBSCRIBERS` | int | 16 | 1-64 | **每种事件类型**下允许的最大订阅者数量。 |
| `CONFIG_EVENT_DISPATCHER_STACK_SIZE` | int | 2048 | 256-8192 | 事件分发线程栈大小（字节）。回调较深或局部变量大时需适当加大。极限配置可设为 256。 |
| `CONFIG_EVENT_DISPATCHER_PRIORITY` | int | 5 | 1-15 | 分发线程优先级（范围 1–15，**数值越小优先级越高**）。 |

### 1.1 事件结构体与 Slab 内存配置

| 配置宏 | 类型 | 默认值 | 范围 | 含义 |
|--------|------|--------|------|------|
| `CONFIG_EVENT_STRUCT_SIZE` | int | 64 | 32/64/128 | 事件结构体大小（字节），决定 inline_data 数组长度。 |
| `CONFIG_EVENT_INLINE_DATA_SIZE` | int | 48 | 4-128 | 内联数据大小阈值。小于此值的数据存储在 inline_data 中，零额外分配。 |
| `CONFIG_EVENT_SLAB_ENABLE` | bool | n | - | 启用 Slab 内存池，实现实时安全分配。`_rt` 后缀 API 完全从 Slab 分配，O(1) 确定时间。 |
| `CONFIG_EVENT_SLAB_CRITICAL_COUNT` | int | 8 | 0-64 | CRITICAL 优先级事件 Slab 块数量（可选）。 |
| `CONFIG_EVENT_SLAB_HIGH_COUNT` | int | 8 | 0-64 | HIGH 优先级事件 Slab 块数量（可选）。 |
| `CONFIG_EVENT_SLAB_NORMAL_COUNT` | int | 16 | ≥4 | NORMAL/LOW 优先级事件 Slab 块数量（必须≥4）。 |
| `CONFIG_EVENT_SLAB_LARGE_ENABLE` | bool | n | - | 启用大数据块 Slab 池（256B/1KB/4KB）。 |
| `CONFIG_EVENT_SLAB_LARGE_256_COUNT` | int | 4 | 0-64 | 256 字节数据块 Slab 数量。 |
| `CONFIG_EVENT_SLAB_LARGE_1K_COUNT` | int | 2 | 0-64 | 1KB 数据块 Slab 数量。 |
| `CONFIG_EVENT_SLAB_LARGE_4K_COUNT` | int | 1 | 0-32 | 4KB 数据块 Slab 数量。 |
| `CONFIG_EVENT_RUNTIME_STATUS` | bool | n | - | 启用 Slab 运行时状态查询 API（`event_slab_available`、`event_get_slab_stats`）。 |
| `CONFIG_EVENT_SLAB_EXHAUSTED_CB` | bool | n | - | 启用 Slab 耗尽回调函数注册。 |
| `CONFIG_EVENT_DEBUG_MEM` | bool | n | - | 启用事件系统内存调试（泄漏检测）。 |

**数据存储策略**：
- `data_len ≤ INLINE_DATA_SIZE`：内联存储于 `event_t.inline_data`，无额外分配
- `data_len ≤ 256`：从 256B 数据 Slab 池分配
- `data_len ≤ 1024`：从 1KB 数据 Slab 池分配
- `data_len ≤ 4096`：从 4KB 数据 Slab 池分配
- `data_len > 4096`：回退到 k_malloc（非实时安全）

**内存占用估算**：
```
事件系统静态内存 ≈ CONFIG_EVENT_MAX_TYPES × (16 + CONFIG_EVENT_MAX_SUBSCRIBERS × 16) 字节
+ CONFIG_EVENT_QUEUE_SIZE × CONFIG_EVENT_STRUCT_SIZE
+ (如启用 Slab) Slab 池总大小
```

**示例**（代码默认值）：
| 配置 | 事件类型 | 订阅者/类型 | 队列深度 | 结构体大小 | Slab 池 | 内存占用 | 适用场景 |
|------|---------|------------|---------|-----------|---------|---------|---------|
| 标准版 | 256 | 8 | 32 | 64B | 启用 | ~30 KB | SRAM ≥ 256KB |
| 平衡版 | 128 | 4 | 16 | 32B | 禁用 | ~8 KB | SRAM 64-128KB |
| 极简版 | 64 | 2 | 8 | 32B | 禁用 | ~2 KB | SRAM 32-64KB |
| **极限版** | **8** | **1** | **4** | **32B** | **禁用** | **~0.5 KB** | **SRAM ≤ 32KB** |

**说明**：事件类型注册、订阅 API 等见 [事件系统详细使用说明.md](../30-核心模块/31-事件系统详细使用说明.md)。

## 2. 模块管理器（Module Manager Configuration）

| 配置宏 | 类型 | 默认值 | 依赖 | 含义 |
|--------|------|--------|------|------|
| `CONFIG_MODULE_MANAGER` | bool | y | — | 是否启用模块管理器：注册/注销、`init/start/stop` 生命周期、与事件订阅集成。 |
| `CONFIG_MAX_MODULES` | int | 16 | `MODULE_MANAGER` | 可同时注册的业务模块**槽位**上限（范围 4–32）。 |
| `CONFIG_MODULE_INIT_TIMEOUT_MS` | int | 1000 | `MODULE_MANAGER` | 单次 `register()` 中调用模块 `init()` 的允许最大耗时（毫秒，范围 100–10000）。超时则注册失败；为 0 表示不检查（以代码为准，见 `module_manager.h`）。 |
| `CONFIG_MODULE_MANAGER_RUNTIME_DEPENDENCIES` | bool | n | `MODULE_MANAGER` | 启用后：`module_manager_start_all()` 按各模块 `depends_on`（模块名字符串数组，NULL 结尾）做拓扑排序；`module_manager_stop_all()` 在 RUNNING 集合上按依赖逆序停止。非法依赖会经不动点剔除；成环或异常时回退为仅按 `priority` 排序。 |
| `CONFIG_MODULE_MANAGER_DEPENDS_LIST_MAX` | int | 16 | `MODULE_MANAGER_RUNTIME_DEPENDENCIES` | **单个模块**的 `depends_on` 中最多扫描多少个依赖名（不含末尾 NULL），防止未正确 NULL 终止时死循环。**不是**全系统模块总数，**不是**依赖链深度。范围 4–64。 |
| `CONFIG_MODULE_MANAGER_START_ALL_ABORT_ON_FAILURE` | bool | n | `MODULE_MANAGER` | 为 y 时：`module_manager_start_all()` 在首次 `start` 返回非 0 后不再启动后续模块。使用运行时依赖时建议开启，避免依赖方在依赖失败仍被启动。 |
| `CONFIG_EXAMPLE_MODULE_MULTI_DEP` | bool | n | `MODULE_MANAGER` | 编译 **`example_module_multi_dep.c`**；其在 **`SYS_INIT`** 中注册（`depends_on` 指向 `example_module_a` / `example_module_b`）。若需观察拓扑序，需同时开启 `RUNTIME_DEPENDENCIES` 并启用 A/B（`APP_CONFIG_ENABLE_MODULE_A`/`B`）。 |
| `CONFIG_EXAMPLE_MODULE_GPIO` | bool | n | `MODULE_MANAGER` | 编译 **`example_module_gpio.c`**；其在 **`SYS_INIT`** 中注册（需板级 DTS 提供 **`led0`**；可选 **`sw0`** 用户键）。 |
| `CONFIG_EXAMPLE_MODULE_UART` | bool | n | `MODULE_MANAGER` | 编译 **`example_module_uart.c`**；其在 **`SYS_INIT`** 中注册（默认绑定 **`zephyr_console`** 对应 UART，可能与 Shell 共用）。 |
| `CONFIG_EXAMPLE_MODULE_UART_USE_ZEPHYR_CONSOLE` | bool | y | `EXAMPLE_MODULE_UART` | 为 y 时使用 `DEVICE_DT_GET(DT_CHOSEN(zephyr_console))`；为 n 时使用 `device_get_binding(CONFIG_EXAMPLE_MODULE_UART_DEVICE_NAME)`。 |
| `CONFIG_EXAMPLE_MODULE_UART_DEVICE_NAME` | string | `UART_0` | `EXAMPLE_MODULE_UART` | 上一项为 n 时的设备名字符串。 |

**说明**：`module_interface_t.depends_on`、`DECLARE_MODULE_*` 宏与示例见 [模块系统详细使用说明.md](../30-核心模块/32-模块系统详细使用说明.md)。GPIO/UART 叠加配置示例见仓库根目录 **`conf/examples/gpio_uart.conf`**。

**依赖版本下限（可选）**：`module_interface_t.depends_version_min` 与 `depends_on[]` 下标一一对应，`0`（`MODULE_DEP_VERSION_ANY`）表示不约束；仅在 **`CONFIG_MODULE_MANAGER_RUNTIME_DEPENDENCIES=y`** 时于拓扑校验阶段比较 `interface->version`（`MODULE_VERSION(major,minor,patch)` 打包整数，非 semver 字符串）。宏 **`DECLARE_MODULE_INTERFACE_WITH_DEPS_VERSION_MIN`** / **`DECLARE_MODULE_INTERFACE_MINIMAL_WITH_DEPS_VERSION_MIN`** 见 `module_base.h`。

## 3. 系统服务（System Services Configuration）

各 **`sys_*`** 模块的职责与使用注意见 **[系统服务使用说明.md](../30-核心模块/36-系统服务使用说明.md)**。下列选项供应用侧服务（日志、内存池、看门狗等）读取；具体是否实现以源码为准。

**`sys_log` 目的地**：由 `sys_log_config_t.destinations`（**`sys_log_dest_mask_t`**）按位选择 `SYS_LOG_DEST_CONSOLE`、`SYS_LOG_DEST_MEMORY`、`SYS_LOG_DEST_RTT`（需 **`CONFIG_SEGGER_RTT`**）、`SYS_LOG_DEST_UART`；掩码为 0 时初始化会回退为「控制台 + 内存环」。

| 配置宏 | 类型 | 默认值 | 含义 |
|--------|------|--------|------|
| `CONFIG_SYS_LOG_LEVEL` | int | 3 | 系统/应用日志级别：0=关闭，1=ERROR，2=WARNING，3=INFO，4=DEBUG。 |
| `CONFIG_SYS_MEMORY_POOL_SIZE` | int | 8192 | 系统内存池大小（字节，范围 1024–65536），用于事件等分配场景时需与 `CONFIG_HEAP_MEM_POOL_SIZE` 等配合。 |
| `CONFIG_SYS_WATCHDOG_ENABLE` | bool | y | 是否启用看门狗相关逻辑（具体喂狗实现见 `sys_watchdog` 等）。 |
| `CONFIG_SYS_WATCHDOG_TIMEOUT_MS` | int | 5000 | 看门狗超时时间（毫秒，范围 1000–30000）。 |

|--------|------|--------|------|------|

| `CONFIG_THREAD_IPC_SERVICE_MAX_PENDING_REQUESTS` | int | 8 | `THREAD_IPC_SERVICE` | 可同时跟踪的未完成请求数量上限（范围 2–64）。 |
| `CONFIG_THREAD_IPC_SERVICE_REQUEST_QUEUE_SIZE` | int | 4 | `THREAD_IPC_SERVICE` | 工作线程侧请求队列深度（静态缓冲，范围 2–32）。 |
| `CONFIG_THREAD_IPC_SERVICE_RESPONSE_QUEUE_SIZE` | int | 4 | `THREAD_IPC_SERVICE` | 分发线程侧响应队列深度（范围 2–32）。 |
| `CONFIG_THREAD_IPC_SERVICE_STACK_SIZE` | int | 1024 | `THREAD_IPC_SERVICE` | **每个**内部线程（worker / dispatcher）的栈大小（字节，范围 512–8192）。 |
| `CONFIG_THREAD_IPC_SERVICE_PRIORITY` | int | 5 | `THREAD_IPC_SERVICE` | 两线程优先级（范围 -16–15，依 Zephyr 约定）。 |
| `CONFIG_THREAD_IPC_SERVICE_LOG_LEVEL` | int | 1 | `THREAD_IPC_SERVICE` | 该模块日志级别：0–4，生产环境建议 0 或 1。 |
| `CONFIG_THREAD_IPC_SERVICE_EXAMPLE` | bool | n | `THREAD_IPC_SERVICE` | 是否编译内置 SYS_INIT 演示代码（与 `example_module_ipc` 二选一可省 RAM）。 |
| `CONFIG_THREAD_IPC_SERVICE_EVENT_BRIDGE` | bool | n | `THREAD_IPC_SERVICE` + `EVENT_SYSTEM` | 启用后将 IPC 结果桥接到事件系统（`ipc_service_event`）。 |
| `CONFIG_THREAD_IPC_SERVICE_SHARED_MEM` | bool | y | `THREAD_IPC_SERVICE` | 启用共享内存池（引用计数管理）。 |
| `CONFIG_THREAD_IPC_SERVICE_SHARED_MEM_POOL_SIZE` | int | 4 | `THREAD_IPC_SERVICE_SHARED_MEM` | 共享内存块数量（范围 2–128）。 |
| `CONFIG_THREAD_IPC_SERVICE_SHARED_MEM_BLOCK_SIZE` | int | 256 | `THREAD_IPC_SERVICE_SHARED_MEM` | 每块大小（字节，范围 64–4096）。 |
| `CONFIG_EXAMPLE_MODULE_THREAD_IPC` | bool | n | `THREAD_IPC_SERVICE` + `MODULE_MANAGER` | 编译 **`example_module_ipc.c`**：由 **`SYS_INIT`** 向 `module_manager` 注册并与 Thread IPC 集成。 |

**内存占用参考**：
- 默认配置（64KB SRAM）：约 4.7 KB
- 极小配置（20KB SRAM）：约 2.1 KB

**说明**：架构与 API 见 **[线程IPC服务使用说明.md](../30-核心模块/33-线程IPC服务使用说明.md)**、**[Thread_IPC模块集成指南.md](../30-核心模块/34-Thread_IPC模块集成指南.md)**。

## 5. Application KV store（掉电保存可选）

根目录 **`Kconfig`** 中菜单 **「Application KV store」**。**`CONFIG_APP_KV_PERSIST`** 依赖 **`CONFIG_FLASH=y`**（片上 Flash 驱动，连带 **`FLASH_PAGE_LAYOUT`** / **`FLASH_HAS_DRIVER_ENABLED`**），以及 **`CONFIG_SETTINGS`**、**`CONFIG_SETTINGS_NVS`** 等。NVS 为 Zephyr 内 **choice** 后端，应用 **Kconfig 不能用 `select`**，须在 **`prj.conf` / fragment** 中按顺序显式打开；典型组合见 **`conf/features/app_kv_persist.conf`**。无 Flash 的目标（如 **`native_posix`**）勿合并持久化配置。

若出现 **`Deprecated symbol FLASH_CODE_PARTITION_ADDRESS_INVALID`**：在 ARM + XIP 且 Flash 基址非 0 时，若 **`/chosen` 未设置 `zephyr,code-partition`**，Kconfig 会把分区地址当作 0 从而选中该弃用项。本仓库 **`boards/nucleo_l4r5zi.overlay`** 已为 **`&flash0` / `partitions` 补充 `ranges`**，并增加 **`slot0_partition`** 与 **`zephyr,code-partition`**，用于消除该警告。若还希望**链接阶段**不把固件放进 `storage` 分区，可再显式 **`CONFIG_USE_DT_CODE_PARTITION=y`**（依赖上述 chosen）。其它板请按 [Zephyr 4.4 迁移说明](https://docs.zephyrproject.org/latest/releases/migration-guide-4.4.html) 为 Flash 与 `fixed-partitions` 补全 `ranges`。上游总览见 [zephyr#104862](https://github.com/zephyrproject-rtos/zephyr/issues/104862)。

| 配置宏 | 类型 | 默认值 | 含义 |
|--------|------|--------|------|
| `CONFIG_APP_KV_PERSIST` | bool | n | 将 **`app_kv`** 整表序列化为单条 Settings 记录写入 flash；启动时 **`app_kv_init()`** 自动加载。需 **`SETTINGS` + `SETTINGS_NVS`** 及 devicetree **`zephyr,settings-partition`**。 |
| `CONFIG_APP_KV_PERSIST_AUTOSAVE` | bool | n | 每次 **`app_kv_set` / `remove` / `clear`** 后写 flash；**磨损大**，一般改用 **`app_kv_save()`** 或 Shell **`app kv save`**。 |

**板级**：`nucleo_l4r5zi` 可使用仓库 **`boards/nucleo_l4r5zi.overlay`**（绑定板级 dts 已有 **`storage_partition`**）。其它板须自行在 chosen 中指定分区。合并配置示例：**`conf/features/app_kv_persist.conf`**。

API：**`app_kv_save()`**、**`app_kv_load()`**（见 **`app_kv.h`**）；错误码 **`APP_ERR_IO`**。

## 6. 应用头文件中的功能开关（非 Kconfig）

`include/zeplod/app_config.h` 中的 **`APP_CONFIG_*`** 等为**编译期宏**，不在 `menuconfig` 中，常见项如下（以文件为准）：

| 宏 | 含义 |
|----|------|
| `APP_CONFIG_ENABLE_MODULE_A` / `B` | 是否为示例模块 A/B 编译 **`SYS_INIT` 自动注册**（见对应 **`example_module_*.c`**）。 |
| `APP_INIT_PRIO_*` | **`SYS_INIT(POST_KERNEL, prio)`** 优先级：同阶段**数值越小越早**；子系统与模块顺序以此为准（勿与线程 `priority`「小值高优先级」混淆时，记住此处仅表示**启动调用顺序**）。 |
| `APP_CONFIG_ENABLE_APP_KV` | 是否启用 RAM 字符串键值表 **`app_kv_*`**（**`APP_INIT_PRIO_APP_KV`** 阶段初始化；默认预置 **`build.target`**）。 |
| `APP_KV_MAX_ENTRIES` / `APP_KV_KEY_MAX_LEN` / `APP_KV_VALUE_MAX_LEN` | 键值表容量与单条 key/value 最大长度（含结尾 `\\0` 前的字符数上限）。 |
| `APP_CONFIG_ENABLE_LOGGING` 等 | 是否启用日志、看门狗、内存管理器、定时器服务等应用层特性。 |
| `APP_CONFIG_ENABLE_STATS` | 为 `1` 时：事件分发器启用运行时统计，Shell **`app events`** 额外打印 `event_dispatcher_get_stats()`；为 `0` 时仅事件系统全局统计。 |
| `APP_CONFIG_ENABLE_LOG_DUMP` | 为 `1` 时 Shell **`app log`** 调用 `sys_log_dump()`；为 `0` 时提示已禁用（仍可通过 API 使用）。 |
| `APP_CONFIG_ENABLE_TOP` | 为 `1` 时 Shell 提供 **`app top [count]`** 运行时快照（模块/事件/内存/Data Bus 聚合/看门狗）；对应 Kconfig **`CONFIG_APP_ENABLE_TOP`**（默认 y，依赖 `CONFIG_APP_ENABLE_SHELL`）。 |

运行时依赖排序与上述开关独立；多依赖示例需 Kconfig 打开 `EXAMPLE_MODULE_MULTI_DEP` 且通常保留 A/B 启用。完整启动顺序见 [模块系统详细使用说明.md](../30-核心模块/32-模块系统详细使用说明.md) 中「应用启动与初始化顺序（Zephyr SYS_INIT）」。

## 8. 可选产品化模块（factory_mode）

定义见 `src/modules/factory/Kconfig`。功能与 API 见 **[46-工厂模式模块使用说明.md](../30-核心模块/46-工厂模式模块使用说明.md)**。叠加片段：**`conf/features/factory_mode.conf`**（产线）、**`conf/targets/production.conf`**（量产默认关闭）。

| 配置宏 | 类型 | 默认值 | 依赖 | 含义 |
|--------|------|--------|------|------|
| `CONFIG_FACTORY_MODE_MODULE` | bool | n | `EVENT_MAX_TYPES > 70` | 工厂产测模块：进入/退出、GPIO 环回、校准暂存与提交；发布事件 **70**。 |
| `CONFIG_FACTORY_MODE_MODULE_AUTOINIT` | bool | y | `FACTORY_MODE_MODULE` | 启动时经 `SYS_INIT` 向 `module_manager` 注册。 |
| `CONFIG_FACTORY_MODE_SHELL` | bool | y | `FACTORY_MODE_MODULE` + `SHELL` | 注册 `factory` Shell 子命令。 |
| `CONFIG_FACTORY_MODE_GPIO_STUB` | bool | y | `FACTORY_MODE_MODULE` | Phase 4 GPIO 环回 stub（同步通过）；真实硬件后端请关闭并实现环回逻辑。 |
| `CONFIG_FACTORY_MODE_CAL_MAX_ENTRIES` | int | 8 | `FACTORY_MODE_MODULE` | RAM 中暂存校准项数量上限（1–32）。 |
| `CONFIG_FACTORY_MODE_CAL_KEY_MAX_LEN` | int | 24 | `FACTORY_MODE_MODULE` | 校准键最大长度（8–64，含结尾 `\\0` 前字符）。 |
| `CONFIG_FACTORY_MODE_CAL_VALUE_MAX_LEN` | int | 64 | `FACTORY_MODE_MODULE` | 校准值最大长度（16–256）。 |

**注意**：`finalize_pass` 依赖 **`CONFIG_APP_KV_ENABLE=y`**，将键写入 `factory.cal.<name>`；无 app_kv 时返回 **`APP_ERR_DISABLED`**。
