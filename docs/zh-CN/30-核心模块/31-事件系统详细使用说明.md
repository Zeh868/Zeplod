## 概述

事件系统是 Zephyr RTOS 框架的核心组件，提供高性能、线程安全的发布 - 订阅（Publish-Subscribe）模式通信机制。该系统支持：

- **异步事件处理**：解耦事件生产者与消费者
- **优先级调度**：支持事件优先级分类
- **线程安全**：所有操作均经过互斥锁保护
- **动态订阅**：运行时动态注册/注销事件类型和订阅者
- **ISR 支持**：支持从中断上下文发布事件

### 主要特性

| 特性 | 描述 |
|------|------|
| 最大事件类型数 | 256 |
| 每类型最大订阅者 | `CONFIG_EVENT_MAX_SUBSCRIBERS` (默认 16) |
| 事件队列大小 | 32 (可配置) |
| 调度器优先级 | 5 (可配置) |
| ISR 安全发布 | 支持 |
| **Slab 内存池** | 优先级分层 + 大数据块池 |
| **实时安全 API** | `_rt` 后缀，O(1) 确定分配时间 |
| **分发器** | 支持暂停/恢复、事件过滤、手动批处理 |

## 核心概念

### 事件（Event）

事件是系统中最基本的通信单元，包含以下字段：

```c
typedef struct {
    uint8_t          type;           // 事件类型标识符
    uint8_t          priority;       // 事件优先级
    uint8_t          flags;          // 标志位 (EVENT_FLAG_*)
    uint8_t          reserved;       // 预留扩展
    uint32_t         timestamp;      // 事件创建时间戳（毫秒 uptime）
    uint32_t         source_id;      // 源模块/组件 ID
    uint32_t         data_len;       // 事件数据长度
    union {
        uint8_t  inline_data[CONFIG_EVENT_INLINE_DATA_SIZE]; // 内联数据
        void*    ptr;                                             // 外部数据指针
    } data;
} event_t;
```

**内存布局**（以 64 字节配置为例）：
```
┌────────────────────────────────┐
│ type(1) priority(1) flags(1) ? │  4B
│ timestamp                      │  4B
│ source_id                      │  4B
│ data_len                       │  4B
├────────────────────────────────┤  16B 头部
│ inline_data[48] 或 ptr(8)      │ 48B
└────────────────────────────────┘  64B 总计
```

**数据存储策略**：
- `data_len ≤ CONFIG_EVENT_INLINE_DATA_SIZE`：内联存储，无额外分配
- `data_len > CONFIG_EVENT_INLINE_DATA_SIZE`：从 Slab 池或 k_malloc 分配

**标志位定义**：
| 标志 | 值 | 含义 |
|------|-----|------|
| `EVENT_FLAG_DATA_INLINE` | 0x01 | 数据内联存储于 inline_data |
| `EVENT_FLAG_DATA_DYNAMIC` | 0x02 | 数据动态分配，由系统管理生命周期 |
| `EVENT_FLAG_FROM_SLAB` | 0x04 | event_t 来自 Slab 池 |
| `EVENT_FLAG_DATA_FROM_SLAB` | 0x08 | 数据来自 Slab 池（随事件释放） |
| `EVENT_FLAG_SLAB_256` | 0x10 | 当前数据落在 256B slab 池 |
| `EVENT_FLAG_SLAB_1K` | 0x20 | 当前数据落在 1KB slab 池 |
| `EVENT_FLAG_SLAB_4K` | 0x40 | 当前数据落在 4KB slab 池 |
| `EVENT_FLAG_SLAB_MASK` | 0x70 | 覆盖三个 slab 大小位的掩码 |

### 事件类型（Event Type）

事件类型用于分类事件，系统支持最多 256 种事件类型。预定义的通用事件类型：

```c
#define EVENT_TYPE_GENERIC        1U    // 通用事件
#define EVENT_TYPE_SENSOR_DATA    10U   // 传感器数据事件
#define EVENT_TYPE_SENSOR_CONFIG  11U   // 传感器配置事件
```

### 订阅者（Subscriber）

订阅者是注册接收特定类型事件的回调函数：

```c
typedef struct {
    event_callback_t callback;      // 回调函数
    void            *user_data;     // 用户数据
    uint32_t         subscriber_id; // 唯一订阅者 ID
    bool             is_active;     // 是否激活
} subscriber_entry_t;
```

### 事件优先级

```c
typedef enum {
    EVENT_PRIORITY_LOW      = 10,   // 低优先级
    EVENT_PRIORITY_NORMAL   = 5,    // 普通优先级
    EVENT_PRIORITY_HIGH     = 2,    // 高优先级
    EVENT_PRIORITY_CRITICAL = 0     // 关键优先级
} event_priority_t;
```

#### 优先级影响处理顺序（须 CONFIG_EVENT_PRIORITY_DISPATCH=y，默认 n）

启用后，事件**按「有效优先级」有序分发**：数值小者先被处理（默认配置仍为 FIFO）。

- **有效优先级与 aging**：`effective = max(priority − age_steps, 0)`，其中
  `age_steps = (now − timestamp) / CONFIG_EVENT_PRIORITY_AGING_STEP_MS`。
  等待越久有效优先级越高（aging 提档），低优先级事件不会饿死。
- **平局规则**：有效优先级相同取 FIFO 最旧。
- **饿死界可推导**：`界 = 最大优先级差 × AGING_STEP + 一个出队周期`。
  例如 LOW(10) 在 CRITICAL(0) 洪泛下，等待 `10 × 100ms = 1s` 后有效优先级归 0，
  与新入 CRITICAL 平局，平局取最旧必胜。
- **仅出队侧重排**：入队路径（含 ISR 发布）零改动；出队时排空队列、按有效优先级
  选最优、其余保序回灌。与 `DROP_LOWEST` 溢出策略共用同一 scratch，互斥串行无冲突。
- **原语义保留**：优先级仍在 `DROP_LOWEST` 入队挤占（满队列时 priority 数值最大者
  被顶替）与 slab 内存隔离（CRITICAL/HIGH/NORMAL 独立池）中生效。
- **timestamp 依赖**：`event_create*` / `event_publish_copy*` 自动写入创建时刻；
  **手搓 `event_t` 必须设置 timestamp**，否则按「严重老化」处理（有效优先级归 0），
  退化为 FIFO 平局次序——不会乱序，但失去优先级语义。
- **约束与正交性**：与 `EVENT_QUEUE_OVERFLOW_BLOCK` 硬互斥（Kconfig 拒绝组合）；
  全局 dispatcher filter 在出队后应用，被拒高优事件仍占用一次最优选择；
  `event_notify_subscribers` 直发不参与排序；统计口径不变，另增
  `aged_promotions`（发生过提档的事件-次计数，见
  `event_dispatcher_get_aged_promotions()`）。

### Sticky 事件（须 CONFIG_EVENT_STICKY=y，默认 n）

Sticky 事件对**显式启用**的类型锁存最近一条事件沿：线程侧发布入队成功后，
事件（元数据 + 负载私有副本）被拷贝进静态槽池；此后**新订阅者订阅成功时，
在订阅线程上下文同步重放一次**该沿，用于「后启动的模块补齐最近状态」。

```c
event_register_type(EVENT_TYPE_GEAR_STATE, "gear_state");
event_sticky_enable(EVENT_TYPE_GEAR_STATE);   /* 不回溯历史：仅锁存启用后的发布 */
event_publish_copy(EVENT_TYPE_GEAR_STATE, EVENT_PRIORITY_NORMAL, &state, sizeof(state));
/* 此后任何 event_subscribe(EVENT_TYPE_GEAR_STATE, ...) 成功即同步收到最近一条沿 */
```

语义要点：

- **发布即锁存最近沿**：仅线程侧发布（`event_publish` / `event_publish_copy`）；
  连发多条只锁存最后一条；`event_publish_from_isr` 不更新锁存沿（ISR 不可持锁）。
- **重放语义**：仅新订阅者（`event_subscribe` / `event_subscribe_filtered`），
  同步调用一次、回调在 sticky 锁外执行；重放不经过订阅级/全局过滤器，
  **不计入 `total_events`**；常规队列投递照常进行（重放不替代分发）。
- **不回溯历史**：`event_sticky_enable` 后的发布才会被锁存；未发布过则订阅无重放、无错误。
- **锁存 best-effort**：负载拷贝失败（slab/堆耗尽或超过 4KB 上界）时发布仍成功，
  保留上一次锁存沿，miss 计数递增并输出 `LOG_WRN`。
- **能力管理**：`clear` 清沿保能力；`disable` 释放负载与槽位；`stop` 不动锁存，
  `shutdown` 释放全部锁存副本；`is_latched` 原子读（ISR 安全）；`get_stats` 输出
  锁存类型数与累计 miss。
- **并发与递归**：槽池由独立互斥锁保护（不与 entry 锁嵌套）；重放回调执行期间
  发布/清除会推迟替换或计 miss，旧负载指针在回调返回前不释放；回调内重入订阅
  其他锁存类型不会递归重放（每线程深度防御）。

### 延迟发布与周期发布（须 CONFIG_EVENT_TIMER_POOL=y，默认 n）

延迟发布与周期发布共享一个静态 `k_timer` 槽池（不新增线程）：到期回调运行于
系统时钟 ISR 上下文，与取消方靠「槽状态机原子 CAS + 世代号（gen）」仲裁竞态。

```c
event_register_type(EVENT_TYPE_HEARTBEAT, "heartbeat");
event_periodic_start(EVENT_TYPE_HEARTBEAT, EVENT_PRIORITY_NORMAL,
                     &beat, sizeof(beat), 1000U, 0U, &handle);   /* 每 1s 自动投递一条副本 */
event_publish_delayed_copy(EVENT_TYPE_HEARTBEAT, EVENT_PRIORITY_NORMAL,
                           &retry, sizeof(retry), 200U, NULL);   /* 200ms 后投递一次 */
event_periodic_cancel(handle);                                   /* 显式停止 */
```

语义要点：

- **延迟发布**：`event_publish_delayed_copy` 提交时把负载深拷贝进槽
  （内联或私有副本，上界 4KB，超出返回 `EVENT_ERR_INVALID_ARG`），
  到期回调以槽内事件壳**零分配**入队；`delay_ms` 1-0x7FFFFFFF，0 按 1 处理。
- **周期发布**：`event_periodic_start` 母本深拷贝入槽，每轮到期经
  `event_create_with_data_rt` **纯 slab 路径**生成全新副本（绝不 `k_malloc`）；
  `initial_delay_ms=0` 表示首投发生在 `period_ms` 时刻（k_timer 原生语义）。
- **到期投递尽力而为**：队列满/未 running/副本分配失败（slab 耗尽）该轮丢弃计
  miss，不重试不补发；一次性槽随即回收，周期槽保留继续下一轮。
- **句柄防 ABA**：`event_timer_handle_t` 为 slot+gen 合体，槽每次回收 gen 递增，
  旧句柄的取消/查询自动失效（`EVENT_ERR_NOT_FOUND`）；取消与到期回调竞态由
  gen 仲裁——回调已通过校验则取消返回 `EVENT_ERR_NOT_FOUND` 不干扰。
- **生命周期**：`stop` 不清 armed（停止期间到期轮次丢弃计 miss，恢复继续）；
  `shutdown` 取消全部槽并释放负载；提交/取消仅线程上下文，ISR 中直接用
  `event_publish_from_isr`。
- **诊断**：`pending_count`（等待到期槽数）、`miss_count`（累计投递失败）、
  `periodic_active_count`（活跃周期槽数）、`get_stats`（按句柄查 fire/miss）。

### 组件说明

1. **事件队列（Event Queue）**
   - 基于 Zephyr `k_msgq` 实现
   - 支持优先级排队
   - 溢出时丢弃新事件

2. **事件调度器（Event Dispatcher）**
   - 独立线程运行
   - 从队列取出事件并通知订阅者
   - 可配置优先级和栈大小

3. **事件类型管理器（Event Type Manager）**
   - 维护事件类型注册表
   - 管理每个类型的订阅者列表
   - 线程安全的访问控制

## 内存与所有权

本节说明事件在 **入队、分发、回调** 各阶段由谁分配、谁释放，避免误用导致 **use-after-free、双重释放或内存泄漏**。

### Slab 内存管理概述

事件系统支持两种内存分配模式：

| 模式 | API | 内存来源 | 实时安全 | 适用场景 |
|------|-----|----------|----------|----------|
| **Slab 模式** | `event_create_rt`, `event_create_with_data_rt` | 预分配 Slab 池 | ✅ O(1) 确定 | ISR、实时任务 |
| **堆模式** | `event_create`, `event_create_with_data` | k_malloc / Slab 回退 | ⚠️ 可能阻塞 | 普通任务 |

**Slab 池架构**：

```
┌─────────────────────────────────────────────────────────────┐
│                    事件 Slab 池 (event_t)                     │
├───────────────┬───────────────┬───────────────────────────┤
│  CRITICAL 池  │   HIGH 池     │      NORMAL/LOW 池        │
│   (可选)      │   (可选)      │        (必须)             │
├───────────────┴───────────────┴───────────────────────────┤
│                    数据 Slab 池 (可选)                       │
├─────────────┬─────────────┬─────────────────────────────┤
│   256B 池   │    1KB 池   │         4KB 池             │
└─────────────┴─────────────┴─────────────────────────────┘
```

**数据存储策略**：
- `data_len ≤ CONFIG_EVENT_INLINE_DATA_SIZE`（默认 48B）：内联存储，零额外分配
- `data_len ≤ 256`：256B 数据池
- `data_len ≤ 1024`：1KB 数据池
- `data_len ≤ 4096`：4KB 数据池
- `data_len > 4096`：回退到 k_malloc（非实时安全）

### 级联 Fallback 机制

`event_memory_select_data_slab_with_fallback` 函数实现了**级联回退**策略：

1. 首选：根据 `data_len` 选择最小合适的 Slab 池（256B → 1KB → 4KB）
2. 检查：如果首选 Slab 池有可用块，直接返回
3. 回退：如果首选池已满，尝试更大的 Slab 池
4. 最终：如果所有 Slab 池都满，回退到 `k_malloc`

**内存放大代价**：

级联回退可能导致"内存放大"——例如 300 字节的数据最终使用 4KB Slab 块。这是因为：
- Slab 块大小是固定的，无法分割
- `EVENT_FLAG_SLAB_*` 标志记录了实际分配来源，确保释放时配对正确

**为什么要用 `EVENT_FLAG_SLAB_*` 标志**：

当数据通过级联 fallback 分配到比实际需求更大的 Slab 时，释放必须回退到正确的 Slab 池。例如：
- 300B 数据首选 256B 池（满）→ 分配到 1KB 池 → 设置 `EVENT_FLAG_SLAB_1K`
- 释放时检查 `EVENT_FLAG_SLAB_*`，将块归还给 1KB 池而非 256B 池

**实时安全注意事项**：

级联 fallback 发生在 `event_create_with_data` 等**非实时**路径。实时安全 API（`_rt` 后缀）不使用 fallback，内存不足时直接返回错误。

### 队列里到底存了什么

事件队列基于 Zephyr `k_msgq` 初始化，单条消息大小为 `sizeof(event_t)`（可配置 32/64/128 字节）：

- `k_msgq_put` 会把调用方传入指针所指的 **`event_t` 整结构体按字节拷贝**到队列环形缓冲区中，**不是**只存「指向 `event_t` 的指针」。
- 结构体里的 `data` 成员是 **联合体**：
  - 小数据（≤ INLINE_DATA_SIZE）：存储在 `inline_data[48]` 中，完整复制
  - 大数据：`ptr` 指针被复制，指向的堆/Slab 内存不复制

分发线程 `k_msgq_get` 时，会把队列槽位里的 `event_t` **再拷贝一份到线程栈上的局部变量**，然后调用 `event_notify_subscribers`，最后在适当时机释放动态分配的数据（见下）。

### `event_publish_copy`（推荐）：模块无需手动释放

流程概要：

1. `event_create_with_data` 分配 **`event_t` 外壳**（优先 Slab，回退 k_malloc）与 **数据缓冲区**（小数据内联，大数据 Slab/k_malloc），并把调用方数据 `memcpy` 进缓冲区。
2. `k_msgq_put` 将 **`event_t` 的值** 写入队列；队列中的副本携带完整事件数据。
3. 入队成功后，实现清除 `EVENT_FLAG_DATA_DYNAMIC` 标志，再 **释放 `event_t` 外壳**（Slab 或 k_free）。
4. 分发线程取出事件、执行回调后，若 `flags & EVENT_FLAG_DATA_DYNAMIC && data.ptr != NULL`，则释放数据内存。

**结论**：走 `event_publish_copy` 时，模块 **不需要** 也 **不应该** 再释放本次事件的 `data` 或 `event_t`；发布失败时由 `event_publish_copy` 内部统一清理。

### `event_publish_copy_rt`（实时安全）：Slab 模式推荐

```c
// ✅ 推荐：ISR 和实时关键任务使用 _rt 后缀 API
void isr_handler(void)
{
    uint8_t data[16] = {0x01, 0x02};
    
    event_status_t ret = event_publish_copy_rt(
        EVENT_TYPE_SENSOR_DATA,
        EVENT_PRIORITY_HIGH,
        data,
        sizeof(data)
    );
    
    if (ret == EVENT_ERR_NO_MEM) {
        // Slab 耗尽，可采取降级措施
    }
}
```

**特点**：
- 完全从 Slab 池分配，O(1) 确定时间
- Slab 耗尽时返回 NULL/错误，**不回退** k_malloc
- 小数据（≤ INLINE_DATA_SIZE）内联存储，零额外分配

### `event_publish`：入队成功后的所有权转移

`event_publish` / `event_publish_from_isr` 将 **`event_t` 按值拷贝** 进 `k_msgq`（见上文「队列里到底存了什么」）。

- **入队成功**：实现会清除调用方 `event` 上的 `EVENT_FLAG_DATA_DYNAMIC` 等动态数据标记，表示 **动态负载已交给队列内副本**；调用方 **不得** 再 `event_free_data()`，但 **可以** 对同一指针调用 `event_free()` 释放 Slab/堆上的 **`event_t` 外壳**（栈上局部变量无需释放）。
- **入队失败**（如 `EVENT_ERR_QUEUE_FULL`）：调用方 **仍拥有** 动态数据，须自行 `event_free_data()` / `event_free()`。

分发线程在处理队列副本时释放动态 `data.ptr`；**不会** 释放你当初 `event_create` 得到的那颗外壳（成功入队后应由调用方 `event_free`）。

因此分情形说明：

| 发布方式 | `event_t` 来源 | 数据存储 | 谁释放 `data` | 谁释放 `event_t` 外壳 |
|----------|---------------|----------|---------------|-------------------------|
| `event_publish_copy` | 内部临时 | 内联/Slab/堆 | 分发线程 | 函数内部 |
| `event_publish_copy_rt` | 内部临时 Slab | 内联/Slab | 分发线程 | 函数内部 |
| `event_publish` + 栈上局部 `event_t` | 栈 | 内联 | 分发线程（副本） | 栈自动结束 |
| `event_publish` + `event_create*` 堆对象 | Slab/堆 | 内联/Slab/堆 | 分发线程（副本） | **入队成功后调用方 `event_free`** |

**实践建议**：

- **普通任务**：优先使用 `event_publish_copy`
- **ISR/实时任务**：使用 `event_publish_copy_rt`
- **栈上小数据**：可使用 `event_publish` + 栈上 `event_t`（数据内联）

### `event_publish_from_isr`

- ISR 中 **推荐** 使用 `event_publish_copy_rt` 或 `event_create_from_isr` + `event_publish`
- 使用实时安全 API 可保证 O(1) 确定时间，避免堆分配的不可预测性
- **技术细节**：`k_msgq_put(K_NO_WAIT)` 在 ISR 中安全，因为 Zephyr `k_msgq` 内部使用 **spinlock**（自旋锁），而非 mutex（互斥锁）
  - **Mutex**：可能阻塞、触发线程调度，ISR 中禁止使用
  - **Spinlock**：只禁用本地中断、不会调度，ISR 中安全

### 订阅回调中的规则

- 回调收到的 `const event_t *event` 指向 **分发线程栈上的副本**，**仅在回调执行期间有效**
- **不要** 保存该指针供异步使用
- **不要** 在回调里 `k_free(event->data.ptr)`：动态数据由分发线程在回调全部返回后释放

### 与「最佳实践」中示例的对应关系

入队成功后：**不要** 再 `event_free_data()`，**不要** 修改已清除动态标记的 `event` 内容；堆上外壳请 **`event_free(event)`**。`event_publish_copy` 则在内部完成外壳与数据的完整生命周期管理。

### 订阅级过滤配置

订阅级过滤默认关闭（默认配置行为零变化）。启用后每个订阅可携带独立过滤器，
在分发线程内、回调之前判定；返回 false 仅跳过该订阅者。

```kconfig
CONFIG_EVENT_SUBSCRIBER_FILTER=y          # 总开关（默认 n）
CONFIG_EVENT_SUBSCRIBER_FILTER_SLOTS=16   # 过滤侧表槽数（默认 16，4-64，约 24B/槽）
CONFIG_EVENT_SUBSCRIBER_FILTER_STATS=y    # skip 计数统计（默认 y）

# 启用时建议评估分发线程栈：
# 快照栈增量最高 256B（64 位；CONFIG_EVENT_MAX_SUBSCRIBERS=16 时），
# 建议 CONFIG_EVENT_DISPATCHER_STACK_SIZE >= 2560
```

内存代价：`subscriber_entry_t` 增加 1 字节 `filter_idx`（32 位目标每槽 +4B；
64 位被尾部 padding 吸收，结构体尺寸不变）。

### Sticky 事件配置

Sticky 事件默认关闭（默认配置行为零变化、零链接残留）。启用后对显式启用的类型
锁存最近一条沿，新订阅者订阅成功时同步重放一次。

```kconfig
CONFIG_EVENT_STICKY=y              # 总开关（默认 n）
CONFIG_EVENT_STICKY_MAX_TYPES=4    # 槽池槽数（默认 4，1-32，约 88B/槽静态）
```

内存代价：静态槽池约 88B/槽（64 位），加每类型一条动态负载副本
（超内联时 slab 优先/k_malloc 回退，单条上界 4KB，超出拒锁存计 miss）；
`event_type_entry_t` 增加 1 字节 `sticky_slot`（被既有布局空隙吸收，
结构体尺寸不变，编译期 BUILD_ASSERT 校验）。

### 延迟/周期发布配置

延迟/周期发布默认关闭（默认配置行为零变化、零链接残留）。启用后延迟与周期
共享一个静态 `k_timer` 槽池，到期回调运行于系统时钟 ISR 上下文，不新增线程。

```kconfig
CONFIG_EVENT_TIMER_POOL=y          # 总开关（默认 n）
CONFIG_EVENT_TIMER_SLOTS=8         # 槽池槽数（默认 8，1-32，延迟与周期共享）
CONFIG_EVENT_PERIODIC_PUBLISH=y    # 周期发布开关（默认 n，依赖 EVENT_TIMER_POOL）
```

内存代价：静态槽池约 130B/槽（32 位目标）。到期投递零 `k_malloc`（一次性槽
提交时深拷贝完毕；周期每轮副本走纯 slab 路径，slab 耗尽该轮丢弃计 miss）。

### 优先级有序分发配置

优先级有序分发默认关闭（默认配置行为零变化，出队仍为 FIFO）。启用后事件按
「有效优先级」有序分发，带 aging 老化防饿死（语义见「核心概念-事件优先级」）。

```kconfig
CONFIG_EVENT_PRIORITY_DISPATCH=y        # 总开关（默认 n；与 EVENT_QUEUE_OVERFLOW_BLOCK 硬互斥）
CONFIG_EVENT_PRIORITY_AGING_STEP_MS=100 # aging 步长（默认 100，10-60000；越小防饿死界越紧）
```

内存代价：每队列 reorder scratch `1 × 容量 × sizeof(event_t)`（默认
CONFIG_EVENT_QUEUE_SIZE=64 时 4KB，init 期一次预分配；与 DROP_LOWEST 溢出策略
组合时额外分配同尺寸回灌缓冲，合计 2×容量），另有分发器侧批缓冲
`容量 × sizeof(event_t)`（默认 4KB）。
与 `EVENT_QUEUE_OVERFLOW_BLOCK` 互斥原因：BLOCK 在 `k_msgq_put` 内驻留发布者，
优先级出队需在 reorder_lock 下排空/回灌队列，组合须入队两段式改造，Kconfig
直接拒绝该组合。

```c
    // 完全从 Slab 池分配，O(1) 确定时间
    event_status_t ret = event_publish_copy_rt(
        MY_EVENT_TYPE_SENSOR_READ,
        EVENT_PRIORITY_HIGH,
        sensor_data,
        sizeof(sensor_data)
    );

        // Slab 池耗尽，采取降级措施
    }
}

// 方法 4: 手动创建和发布（不推荐，易泄漏）
void manual_publish(const void *data, size_t len)
{
    event_t *event = event_create_with_data(
        MY_EVENT_TYPE_SENSOR_READ,
        EVENT_PRIORITY_NORMAL,
        data,
        len
    );
    if (event == NULL) {
        return;
    }
    if (event_publish(event) != EVENT_OK) {
        event_free(event);  // 发布失败，释放整颗事件

    // 推荐改用 event_publish_copy，避免遗漏
}
```

```c
// 定义事件类型
#define EVENT_TYPE_BUTTON    50U
#define EVENT_TYPE_LED       51U

// 全局订阅者 ID
static uint32_t button_sub_id;
static uint32_t led_sub_id;

// 按钮事件回调
static void button_callback(const event_t *event, void *user_data)
{
    LOG_INF("Button event received: data_len=%u", event->data_len);
    
    if (event->data_len == sizeof(uint8_t)) {
        // 小数据内联存储，直接从 inline_data 读取
        uint8_t button_state;
        if (event->flags & EVENT_FLAG_DATA_INLINE) {
            button_state = event->data.inline_data[0];
        } else {
            button_state = *(uint8_t *)event->data.ptr;
        }
        LOG_INF("Button state: %s", button_state ? "PRESSED" : "RELEASED");
    }
}

// LED 事件回调
static void led_callback(const event_t *event, void *user_data)
{
    LOG_INF("LED event received");
    
    if (event->data_len == sizeof(uint8_t)) {
        uint8_t led_state;
        if (event->flags & EVENT_FLAG_DATA_INLINE) {
            led_state = event->data.inline_data[0];
        } else {
            led_state = *(uint8_t *)event->data.ptr;
        }
        // 控制 LED
        LOG_INF("LED turned %s", led_state ? "ON" : "OFF");
    }
}

// 按钮线程（发布按钮事件）
static void button_thread(void *p1, void *p2, void *p3)
{
    while (1) {
        uint8_t button_state = 1;  // 模拟按钮按下
        
        event_publish_copy(
            EVENT_TYPE_BUTTON,
            EVENT_PRIORITY_NORMAL,
            &button_state,
            sizeof(button_state)
        );

        k_msleep(1000);
        
        button_state = 0;  // 模拟按钮释放
        event_publish_copy(
            EVENT_TYPE_BUTTON,
            EVENT_PRIORITY_NORMAL,
            &button_state,
            sizeof(button_state)
        );

        k_msleep(1000);
    }
}

// LED 控制线程（发布 LED 事件）
static void led_thread(void *p1, void *p2, void *p3)
{
    k_sleep(K_SECONDS(2));  // 等待按钮线程先启动

    while (1) {
        uint8_t led_state = 1;  // LED ON
        
        event_publish_copy(
            EVENT_TYPE_LED,
            EVENT_PRIORITY_LOW,
            &led_state,
            sizeof(led_state)
        );

        k_msleep(500);
        
        led_state = 0;  // LED OFF
        event_publish_copy(
            EVENT_TYPE_LED,
            EVENT_PRIORITY_LOW,
            &led_state,
            sizeof(led_state)
        );

        k_msleep(500);
    }
}

{
```

## 最佳实践

### 发布、卸载与手动消费契约

| 场景 | 要求 |
|------|------|
| **发布** | 先 `event_register_type`；优先 `event_publish_copy` / `event_create_with_data`。`event_publish` / `event_publish_from_isr` 会校验 `flags` 与 `data_len`，手搓不一致的 `event_t` 返回 `EVENT_ERR_INVALID_ARG` |
| **模块卸载** | `event_system_stop()` → `event_unsubscribe_all(subscriber_id)` → 再释放 `user_data`。`event_unsubscribe` 返回后，分发器仍可能执行已快照的旧回调 |
| **手动 `process_one` / `process_all`** | 仅在 **init 后、首次 `event_dispatcher_start()` 之前** 使用。曾 start 后再 stop，或分发器 `RUNNING` 时由其他线程调用，会返回 `EVENT_ERR_INVALID_ARG` |
| **`DROP_LOWEST` 溢出策略** | 仅线程侧 `event_publish` 会按优先级挤占队列槽位；`event_publish_from_isr` 在队列满时仍为 `DROP_NEWEST` |
| **订阅级 filter**（须 `CONFIG_EVENT_SUBSCRIBER_FILTER=y`） | 分发线程回调前判定；返回 false 仅跳过该订阅者；与全局 dispatcher filter 独立叠加且**全局先判**；filter 回调在分发线程内执行，不得阻塞/发布/调订阅 API |
| **Sticky 事件**（须 `CONFIG_EVENT_STICKY=y`） | 先 `event_sticky_enable(type)` 再发布；仅锁存启用后的线程侧发布最近一条沿（不回溯历史，ISR 发布不更新）；新订阅者订阅成功时在订阅线程同步重放一次，不经过滤器、不计入 `total_events`；锁存 best-effort（拷贝失败发布仍成功、计 miss）；未注册/槽池满 enable 返回 `EVENT_ERR_NOT_FOUND`；`shutdown` 释放全部锁存副本 |
| **延迟/周期发布**（须 `CONFIG_EVENT_TIMER_POOL=y`；周期另须 `CONFIG_EVENT_PERIODIC_PUBLISH=y`） | 延迟 `event_publish_delayed_copy` 深拷贝入槽（上界 4KB）后到期自动投递一次，周期 `event_periodic_start` 每轮以母本生成纯 slab 新副本自动重发；到期投递**尽力而为**（队列满/未 running/副本分配失败该轮丢弃计 miss，**不补发**）；句柄 slot+gen 防 ABA，取消与到期回调竞态由 gen 仲裁（回调已通过校验返回 `EVENT_ERR_NOT_FOUND` 不干扰）；`stop` 不清 armed（**停止期间轮次丢弃计 miss 不补发**，恢复继续）；`shutdown` 取消全部并释放负载；提交/取消仅线程上下文 |
| **优先级有序分发**（须 `CONFIG_EVENT_PRIORITY_DISPATCH=y`，默认 n；与 `EVENT_QUEUE_OVERFLOW_BLOCK` **硬互斥**） | 出队按有效优先级 `max(priority − (now−timestamp)/AGING_STEP, 0)` 排序，平局取 FIFO 最旧；入队与 ISR 路径零改动；**事件 `timestamp` 须为创建时刻**（`event_create*`/`publish_copy*` 已满足，手搓 `event_t` 必须设置，否则退化为 FIFO）；手动 `process_one`/`process_all` 开启后亦有序（行为变化点）；全局 dispatcher filter 在出队后应用，被拒高优事件仍占用一次最优选择；`event_notify_subscribers` 直发不参与排序；与 `DROP_LOWEST` 共用 scratch 互斥串行；饿死界 = 最大优先级差 × AGING_STEP + 一个出队周期；统计另增 `aged_promotions`（提档事件-次），口径不变 |

```c
    event_publish(&event);
}

// ⚠️ 避免手动管理：event_create_with_data + event_publish 易泄漏
// 推荐改用 event_publish_copy 或 event_publish_copy_rt
```

### 4. 错误处理

```c
void robust_publish(const void *data, size_t len)
{
    event_status_t ret = event_publish_copy(
        EVENT_TYPE_SENSOR_DATA,
        EVENT_PRIORITY_NORMAL,
        data,
        len
    );

    switch (ret) {
    case EVENT_OK:
        // 成功
        break;
    case EVENT_ERR_QUEUE_FULL:
        LOG_WRN("Event queue full, data dropped");
        break;
    case EVENT_ERR_INVALID_ARG:
        LOG_ERR("Invalid event arguments");
        break;
    case EVENT_ERR_NO_MEM:
        LOG_ERR("Memory allocation failed");
        break;
    default:
        LOG_ERR("Unknown error: %d", ret);
        break;
    }
}
```

## 故障排除

### 常见问题

#### 1. 事件未送达

**症状**：发布事件后回调未执行

**检查清单**：
- [ ] 事件类型是否已注册？
- [ ] 订阅者是否成功订阅？
- [ ] 事件调度器是否已启动？
- [ ] 回调函数是否正确实现？

```c
// 调试步骤
void debug_event_delivery(void)
{
    // 检查事件类型
    LOG_INF("Event type name: %s", event_get_type_name(MY_EVENT_TYPE));

    // 检查订阅者数量
    uint32_t count = event_get_subscriber_count(MY_EVENT_TYPE);
    LOG_INF("Subscriber count: %u", count);

    // 检查系统状态
    LOG_INF("System running: %s", 
            event_system_is_running() ? "yes" : "no");
}
```

#### 2. 队列溢出

**症状**：日志显示 "Event queue full, event dropped"

**解决方案**：
```kconfig
# 增加队列大小
CONFIG_EVENT_QUEUE_SIZE=128

# 或优化事件处理速度
# 减少回调中的处理时间
```

#### 3. 内存泄漏 / 野指针

**症状**：系统运行一段时间后内存不足，或随机崩溃

**检查点**：
- 优先使用 `event_publish_copy`；详见 [内存与所有权](#内存与所有权)
- `event_publish` + `event_create*`：分发线程**不会**释放 `event_t` 外壳，堆路径易泄漏；失败路径须 `event_free`
- **禁止** `event_publish` 的 `data` 指向发布函数内的局部栈缓冲（回调可能晚于函数返回）
- ISR 中避免堆分配；`data` 指向的内存在分发前须一直有效
- 回调内不要 `k_free(event->data)`（除非项目另有所有权约定）

#### 4. 死锁问题

**症状**：系统卡死，看门狗复位

**原因**：在事件回调中调用可能阻塞的 API

**解决方案**：
```c
// ❌ 错误示例
static void bad_callback(const event_t *event, void *user_data)
{
    k_mutex_lock(&some_mutex, K_FOREVER);  // 可能死锁
}

// ✅ 正确示例
static void good_callback(const event_t *event, void *user_data)
{
    k_sem_give(&processing_sem);  // 非阻塞
}
```

### 错误码说明

| 错误码 | 值 | 描述 |
|--------|-----|------|
| EVENT_OK | 0 | 成功 |
| EVENT_ERR_NO_MEM | -1 | 内存不足 |
| EVENT_ERR_QUEUE_FULL | -2 | 队列已满 |
| EVENT_ERR_QUEUE_EMPTY | -3 | 队列为空 |
| EVENT_ERR_INVALID_ARG | -4 | 无效参数 |
| EVENT_ERR_NOT_FOUND | -5 | 未找到 |
| EVENT_ERR_NO_SUBSCRIBER | -6 | 无订阅者 |
| EVENT_ERR_TIMEOUT | -7 | 超时 |
| EVENT_ERR_NOT_RUNNING | -8 | 事件系统/分发器未启动 |
