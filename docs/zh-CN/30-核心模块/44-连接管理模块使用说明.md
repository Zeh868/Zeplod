# 连接管理模块使用说明（connectivity_module）

本文说明可选 **`connectivity_module`**（`CONFIG_CONNECTIVITY_MODULE`）：抽象链路 up/down，通过事件 **60**（`EVENT_CONNECTIVITY_STATE_CHANGED`）广播状态。Phase 3 默认 **null 后端**（同步模拟连接）；Phase 4 追加 Wi-Fi 后端；Phase 5 起改为**优先级注册表 + 运行时 failover**：可同时启用多个后端（null/Wi-Fi/以太网/蜂窝），按各自 `CONFIG_CONNECTIVITY_BACKEND_*_PRIORITY` 择优连接，活动链路掉线自动切换到下一个可用后端（`CONFIG_CONNECTIVITY_FAILOVER`），高优先级恢复后可选抢占升级（`CONFIG_CONNECTIVITY_FAILOVER_PREEMPT`）。

**要求：** `CONFIG_EVENT_MAX_TYPES > 60`

**相关**：[32-模块系统详细使用说明.md](32-模块系统详细使用说明.md) · [45-配网模块使用说明.md](45-配网模块使用说明.md)

## 1. 启用

```bash
west build -b <board> . -- -DEXTRA_CONF_FILE=conf/features/connectivity.conf
```

三合一 stub：

```bash
west build -b <board> . -- -DEXTRA_CONF_FILE=conf/features/net_stub.conf
```

## 2. 状态与事件

| 字段 | 说明 |
|------|------|
| `connectivity_state_t` | DOWN / CONNECTING / UP / ERROR |
| `connectivity_link_type_t` | NONE / WIFI / ETHERNET / BLE / CELLULAR |
| 事件负载 | `connectivity_status_t`（state + link_type + error_code） |

---

## 3. API

模块生命周期遵循 `module_interface_t`；业务侧常用：

```c
int connectivity_module_connect(connectivity_link_type_t link_type);
int connectivity_module_connect_auto(void);
int connectivity_module_disconnect(void);
int connectivity_module_get_state(connectivity_status_t* out);
```

`connectivity_module_connect(link_type)` 须模块已 **start**（`MODULE_STATUS_RUNNING`）；在已注册后端中按 `link_type` 精确匹配并只连它（未命中时退化到 null 通配后端，兼容单 null 后端场景）；在 null 后端下同步进入 `CONNECTIVITY_STATE_UP`；已连接同一后端时再次 connect 幂等返回 0。

`connectivity_module_connect_auto()` 按注册表 priority 从高到低择优连接，跳过 `is_available()` 为 false 的后端；启用 `CONFIG_CONNECTIVITY_FAILOVER` 时活动链路掉线会自动调用本函数重选，也可业务侧主动调用触发一次择优连接。

---

## 4. 后端扩展与优先级

实现 `connectivity_backend_ops_t`（见 `connectivity_backend.h`；`is_link_up`/`is_available` 须非阻塞，`init`/`connect`/`disconnect` 允许阻塞），通过独立的 `CONFIG_CONNECTIVITY_BACKEND_*` bool 启用一个或多个后端（不再互斥），各自的 `CONFIG_CONNECTIVITY_BACKEND_*_PRIORITY`（0~100，越大越优先）决定 `connect_auto()`/failover 的择优顺序。内置后端：null（默认开启，兼容 ztest）、Wi-Fi、以太网（`connectivity_backend_ethernet.c`）、蜂窝（`connectivity_backend_cellular.c`，见下节）。

---

## 5. 蜂窝后端支持的常见 modem 型号与用户配置

蜂窝后端（`CONFIG_CONNECTIVITY_BACKEND_CELLULAR`）**与具体型号解耦**：它驱动 Zephyr 通用 `CONFIG_MODEM_CELLULAR` 驱动统一暴露的 PPP 网口生命周期（`net_if_up()` 触发附着/拨号 → 等待 conn_mgr `NET_EVENT_L4_CONNECTED` → `net_if_down()` 断开），选型号只是换 DT 绑定，后端代码无需改动。

**modem_cellular 已支持的 DT compatible（即支持的型号，Zephyr v4.4）：**

| 厂商 | compatible |
|------|-----------|
| Quectel | `quectel,bg95` / `bg96` / `bg9x` / `eg25-g` / `eg800q` / `eg915u` |
| SIMCom | `simcom,sim7080` / `simcom,a76xx` |
| u-blox | `u-blox,sara-r4` / `sara-r5` / `lara-r6` |
| Telit | `telit,me310g1` / `me910g1` / `le910c1tx` / `lex10q1` |
| Sierra | `swir,hl7800` / `swir,hl78xx`（及 gnss/offload 变体） |
| 其他 | `sqn,gm02s`、`trasna,lexi-r10`、`nordic,nrf91-slm` / `nrf93m1` |

**用户按硬件必须配置的项（本后端不代配）：**

1. **DT 绑定 modem 节点**：在板级 overlay 里把上表某个 compatible 的节点挂到承载 modem 的 UART 上，并加标准别名 `aliases { modem = &your_modem_node; };`（有此别名时本后端才会经 `PM_DEVICE` 对 modem 做 resume/suspend；无别名则退化为仅 `net_if_up/down`，依赖驱动自启）。参考 `zephyr/samples/net/cellular_modem/boards/*.overlay`。
2. **APN**：由驱动 Kconfig `CONFIG_MODEM_CELLULAR_APN` 配置（留空则驱动等待应用调用 `cellular_set_apn()`），**不在**本模块的 Kconfig 里。
3. 选中本后端会自动 `select NET_L2_PPP` + `NET_CONNECTION_MANAGER`（PPP 网口与 L4 事件的来源），无需手动开；modem 硬件还需 UART/电源/复位等引脚的 DT 配置，按所选模块的 binding 文档补齐。

> 本仓库无蜂窝硬件，蜂窝后端仅做过 build-only 验证；端到端需在绑定真实 modem 的板子上验证。
