# 连接管理模块使用说明（connectivity_module）

本文说明可选 **`connectivity_module`**（`CONFIG_CONNECTIVITY_MODULE`）：抽象链路 up/down，通过事件 **60**（`EVENT_CONNECTIVITY_STATE_CHANGED`）广播状态。Phase 3 默认 **null 后端**（同步模拟连接）；Phase 4 追加 Wi-Fi 后端；Phase 5 起改为**优先级注册表 + 运行时 failover**：可同时启用多个后端（null/Wi-Fi/以太网/蜂窝），按各自 `CONFIG_CONNECTIVITY_BACKEND_*_PRIORITY` 择优连接，活动链路掉线自动切换到下一个可用后端（`CONFIG_CONNECTIVITY_FAILOVER`），高优先级恢复后可选抢占升级（`CONFIG_CONNECTIVITY_FAILOVER_PREEMPT`）。

**要求：** `CONFIG_EVENT_MAX_TYPES > 60`

**相关**：[32-模块系统详细使用说明.md](32-模块系统详细使用说明.md) · [45-配网模块使用说明.md](45-配网模块使用说明.md)

## 2. 状态与事件

| 字段 | 说明 |
|------|------|
| `connectivity_state_t` | DOWN / CONNECTING / UP / ERROR |
| `connectivity_link_type_t` | NONE / WIFI / ETHERNET / BLE / CELLULAR |
| 事件负载 | `connectivity_status_t`（state + link_type + error_code） |

---

## 3. API

模块生命周期遵循 `module_interface_t`；业务侧常用：

```c
int connectivity_module_connect(connectivity_link_type_t link_type);
int connectivity_module_connect_auto(void);
int connectivity_module_disconnect(void);
int connectivity_module_get_state(connectivity_status_t* out);
```

`connectivity_module_connect(link_type)` 须模块已 **start**（`MODULE_STATUS_RUNNING`）；在已注册后端中按 `link_type` 精确匹配并只连它（未命中时退化到 null 通配后端，兼容单 null 后端场景）；在 null 后端下同步进入 `CONNECTIVITY_STATE_UP`；已连接同一后端时再次 connect 幂等返回 0。

`connectivity_module_connect_auto()` 按注册表 priority 从高到低择优连接，跳过 `is_available()` 为 false 的后端；启用 `CONFIG_CONNECTIVITY_FAILOVER` 时活动链路掉线会自动调用本函数重选，也可业务侧主动调用触发一次择优连接。

---

## 4. 后端扩展与优先级

实现 `connectivity_backend_ops_t`（见 `connectivity_backend.h`；`is_link_up`/`is_available` 须非阻塞，`init`/`connect`/`disconnect` 允许阻塞），通过独立的 `CONFIG_CONNECTIVITY_BACKEND_*` bool 启用一个或多个后端（不再互斥），各自的 `CONFIG_CONNECTIVITY_BACKEND_*_PRIORITY`（0~100，越大越优先）决定 `connect_auto()`/failover 的择优顺序。内置后端：null（默认开启，兼容 ztest）、Wi-Fi、以太网（`connectivity_backend_ethernet.c`）、蜂窝骨架（`connectivity_backend_cellular.c`，需自行绑定 modem 驱动，见其文件头说明）。
