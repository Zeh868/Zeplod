## 从模板复制后的检查清单

将本仓库**整体复制为新产品**（单仓库、非子模块）时，建议按下面清单逐项核对，避免路径、版本与 CI 长期漂移。

1. **west.yml**：`revision` 与团队使用的 Zephyr 版本一致（默认 **v3.6.0**，与 **[Zephyr版本与CI说明.md](../70-发布与产品化/72-Zephyr版本与CI说明.md)**、CI 镜像一致）；若使用公司内镜像，修改 `url`。
2. **zephyr_config.env**：从 **`zephyr_config.env.template`** 复制，填写 **`ZEPHYR_BASE`**、**`ZEPHYR_SDK_INSTALL_DIR`**；**不要提交**到 Git（仓库 **`.gitignore`** 已包含该文件）。若历史曾误提交过，需从索引中移除：`git rm --cached zephyr_config.env`（再提交一次）。
3. **CMake 工程名**：根目录 **`CMakeLists.txt`** 中 **`project(...)`** 改为你的产品名。
4. **版本与文档**：根目录 **`APP_VERSION`**、**`README.md`** 标题与产品说明按需更新。
5. **板型与 CI**：**`prj.conf`**、**`.github/workflows/ci.yml`**（及若使用 GitLab：**`.gitlab-ci.yml`**）中 ARM 构建矩阵的 **`board`** 与目标硬件或 CI 策略一致；文档中的示例板名（如 `nucleo_l4r5zi`）仅作演示，**以你实际 `BOARD` 与 CI 为准**。托管平台上启用 CI 的逐步说明见 **[CI平台配置保姆级手册.md](../50-测试与CI/52-CI平台配置保姆级手册.md)**。
6. **示例模块**：**`src/modules_examples/example_*`** 可删除或改为业务模块（公开头文件在 **`include/zeplod/`**）；同步 **`CMakeLists.txt`**、Kconfig，以及各模块 **`.c`** 中的 **`SYS_INIT` 注册**与 **`include/zeplod/app_config.h`** 中的 **`APP_INIT_PRIO_*`**（不必再集中改 **`app_main.c`** 注册列表）。
7. **可选钩子**：本地安装 **`pre-commit`**（见 **[参与贡献与代码规范.md](../80-贡献与维护/81-参与贡献与代码规范.md)**）可与 CI 中 **`pre-commit run --all-files`** 行为对齐。

## 开发工作流

### 添加新模块

1. 创建公开头文件 `include/zeplod/my_module.h` 与实现 `src/modules/my_module.c`
2. 实现模块接口（`#include <zeplod/module_base.h>`）
3. 在 `CMakeLists.txt` 中添加 `.c` 源文件
4. 在 **`include/zeplod/app_config.h`** 中增加 **`APP_INIT_PRIO_MODULE_*`**（介于 **`APP_INIT_PRIO_MODULE_MGR`** 与 **`APP_INIT_PRIO_APP_FINAL`** 之间）
5. 在 **`my_module.c`** 末尾用 **`SYS_INIT(..., POST_KERNEL, APP_INIT_PRIO_MODULE_*)`** 调用 **`module_manager_register()`**（参考 **`example_module_a.c`**）

可选：模块间启动顺序若需按依赖排列，见 [模块系统详细使用说明.md](../30-核心模块/32-模块系统详细使用说明.md) 中的「应用启动与初始化顺序（Zephyr SYS_INIT）」与「运行时依赖」；多依赖示例见 `src/modules_examples/example_module_multi_dep.c`。

### 添加事件类型

```c
// 在模块头文件中定义
#define EVENT_TYPE_MY_EVENT  100

// 注册事件类型
event_register_type(EVENT_TYPE_MY_EVENT, "my_event");

// 订阅事件
event_subscribe(EVENT_TYPE_MY_EVENT, my_callback, user_data, &id);

// 发布事件
event_publish_copy(EVENT_TYPE_MY_EVENT, EVENT_PRIORITY_NORMAL, &data, sizeof(data));
```

**事件系统使用契约（必读）**

| 场景 | 做法 |
|------|------|
| 发布 | 先注册类型；优先 `event_publish_copy` / `event_create_with_data`，不要手填不一致的 `flags` 与 `data_len`（`event_publish` 会校验并返回 `EVENT_ERR_INVALID_ARG`） |
| 模块卸载 | `event_system_stop()` → `event_unsubscribe_all(subscriber_id)` → 再释放 `user_data`（取消订阅后分发器仍可能执行已快照的回调） |
| 手动消费队列 | 仅 **init 后从未** `event_dispatcher_start()` 时可手动 `process_one` / `process_all`；曾 start 后再 stop 或与 RUNNING 的分发器线程并行调用会被拒绝 |
| 队列满策略 `DROP_LOWEST` | 仅线程侧 `event_publish` 会按优先级挤占；ISR 满队列仍为丢弃新事件（`DROP_NEWEST`） |

更完整的 API 说明见 [事件系统详细使用说明.md](../30-核心模块/31-事件系统详细使用说明.md)。

### 状态机与锁序（核心模块）

框架在 `src/core/` 提供 **`state_machine`**（生命周期）与 **`lock_order`**（多锁顺序登记），已在 **`event_system`**、**`module_manager`**、**`ipc_service`** 落地。

| 要点 | 说明 |
|------|------|
| 状态机 API | `zepl_state_machine_init`、`zepl_state_machine_try_transition`、`zepl_state_machine_get`（见 `include/zeplod/state_machine.h`） |
| 锁序 API | `zepl_lock_enter` / `zepl_lock_exit` 与 `k_mutex` 成对使用；层级 GLOBAL → STATE → TABLE → ENTRY → RESOURCE |
| 新模块 | 有 init/start/stop 则嵌入 `zepl_state_machine_t`；每把互斥锁挂锁序；持锁不调外部回调 |
| 注意 | `event_system` 不用 `ZEP_STATE_ERROR`；`module_manager` 仅一把全局锁；IPC pending 释放 shm 时为 TABLE→ENTRY 嵌套 |

实施计划与刻意保留的设计说明：**[2026-05-23-state-machine-lock-ordering-implementation-plan.md](../../superpowers/plan/2026-05-23-state-machine-lock-ordering-implementation-plan.md)**（仓库 `docs/superpowers/plan/`）。

### 修改配置

- `prj.conf` - Zephyr 内核与应用合并配置（`CONFIG_*`）
- `Kconfig` - 本应用扩展的菜单项定义（根目录与 `src/modules/ipc_service/Kconfig`）
- `zephyr_config.env` - 本地路径配置
- `include/zeplod/app_config.h` - 应用功能开关（`APP_CONFIG_*` 等宏，非 menuconfig）

**各配置项含义**：见 **[项目配置项说明.md](../40-应用开发/42-项目配置项说明.md)**（事件系统、模块管理器、系统服务、Thread IPC、`app_config` 补充说明）。

## 代码规范

### 格式化代码

```bash
# 使用 clang-format（仓库根目录 .clang-format）
clang-format -i src/**/*.c src/**/*.h

例如：
    clang-format -i src\app\*.c src\app\*.h
    clang-format -i src\core\*.c src\core\*.h
    clang-format -i src\modules\ipc_service\*.c src\modules\ipc_service\*.h
    clang-format -i src\modules\*.c src\modules\*.h
    clang-format -i src\services\*.c src\services\*.h
### pre-commit（可选）

```bash
pip install pre-commit
pre-commit install
pre-commit run --all-files
```

配置见仓库根目录 `.pre-commit-config.yaml`（含行尾空白、YAML 检查、clang-format）。

### 静态分析（clang-tidy）

仓库提供 `.clang-tidy`（可按项目收紧或放宽检查项）。需先配置 Zephyr 构建以生成 `compile_commands.json`，例如：

```bash
west build -b native_posix . -- -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
clang-tidy -p build src/core/event_system.c
```

无 `compile_commands.json` 时，仅能用 `clang-tidy ... -- -I...` 手动传头，易与 Zephyr 不一致，建议优先用 `-p build`。

### 命名约定

| 类型 | 命名风格 | 示例 |
|------|---------|------|
| 文件 | snake_case | `event_system.c` |
| 函数 | snake_case | `event_publish()` |
| 类型 | snake_case_t | `event_t`, `event_status_t` |
| 枚举值 | UPPER_CASE | `EVENT_OK`, `EVENT_ERR` |
| 宏 | UPPER_CASE | `EVENT_MAX_SUBSCRIBERS` |
| 变量 | lower_case | `subscriber_id` |
| 模块名 | snake_case | `module_manager` |

```c

ZTEST(test_module, test_feature)
{
    // 测试代码
    zassert_equal(expected, actual, "错误消息");
}

ZTEST_SUITE(test_module, NULL, NULL, NULL, NULL, NULL);
```

## 常见问题

### Q: 如何更改目标开发板？

A: 修改构建命令中的 `-b` 参数：
```bash
west build -b nucleo_l4r5zi . -p always
```

### Q: 如何添加新的 Kconfig 选项？

A: 在 `Kconfig` 文件中添加：
```kconfig
config MY_FEATURE
    bool "Enable my feature"
    default y
    help
      Enable this feature to...
```

然后在 `prj.conf` 中启用：
```
CONFIG_MY_FEATURE=y
```

### Q: 如何调试内存问题？

A: 使用内存统计和泄漏检测：
```c
sys_mem_dump_allocations(SYS_MEM_POOL_GENERAL);
uint32_t leaks = sys_mem_check_leaks(SYS_MEM_POOL_GENERAL);
```
